# 週6: 既存コードを読み解く — AIを相棒に、初見の中規模リポを歩く

ここから、研修の題材が変わります。これまでは「自分でゼロから作る」課題でした。今週からは**他人が書いた、すでに動いているシステム**——[題材リポ（図書貸出管理API）](../project-repo/)——に向き合います。
現場であなたが最初に任される動きは「ゼロから作る」ではなく、**既存のコードを読んで、直して、足す**こと。その第一歩が「読む」です。
全体の進め方・AI利用ルール・質問テンプレート・日報フォーマットは、先に [研修トップのREADME](../README.md) を読んでください。

> この週は第2フェーズ（AI協働）の後半の入口です。**AIにコードを読ませて要約させてよい**——ただし週5で身につけた「疑って裏を取る」構えをそのまま使います。**AIの要約を鵜呑みにせず、必ず自分でコードを開いて確かめる**。これが週7以降（安全な改修・参画）で「壊さず直す」ための土台になります。

---

## 1. この週の狙い（到達目標）

> **初見の中規模リポを渡されたら、AIの助けも借りて、全体像と該当箇所を自力で把握できる。**

現場に配属されると、あなたは**自分が書いたのではない、大きめのコードベース**にいきなり参加します。仕様書が完璧に揃っていることは稀で、「この機能どこで動いてるの？」を**コードから自分で探す**力が要ります。

この週で身につけること:

- **中規模リポの歩き方**: どこから読み始めるか（エントリポイント）、フォルダ構成から役割を推測する
- **処理フローを追う**: 1つのAPIが、Controller → Service → Mapper → XML(SQL) と、どのファイルのどの行を通って動くかを追う
- **3層構造の地図化**: 「窓口・判断・DB出し入れ」のどこに何があるかを、自分の言葉で地図にする
- **AIの要約を裏取りする読み方**: AIに「このコードは何をしている？」と要約させ、**その要約が本当か自分でコードを開いて確かめる**

> 用語メモ: **エントリポイント** … プログラムの入口。Spring Bootアプリなら `main` メソッドのある起動クラス（この題材では `LibraryApplication.java`）や、外からのリクエストを最初に受ける Controller。
> 用語メモ: **処理フロー** … 1つの操作（例: 本を借りる）が、どのファイルのどのメソッドを、どの順で通って実現されるかの流れ。

---

## 2. AI利用区分（この週のルール）

✅ **週6は、AIを「読解の相棒」として使ってよいです。** ただし条件があります。

- ✅ AIに「このファイルは何をしている？」「この処理はどこから呼ばれる？」と聞いてよい
- ✅ ただし **AIの要約・回答を鵜呑みにしない**。必ず**自分でそのファイルを開き、その行を見て**確かめる
- 🚫 「AIがこう言ったから」だけで完了にするのは不可。**最終的な理解は自分の言葉で**説明できること

> 週5で「AIは自信満々に間違える」を体で知りましたね。読解でも同じです。AIは「たぶんここでしょう」を断言します。**それが本当にそのファイル・その行か**を、自分の目で確認する。この裏取りが、週7で「壊さず直す」ときに効いてきます。

理由の詳細は [研修トップのREADME「2. AI利用ルール」](../README.md#2-ai利用ルール最重要必ず守る) を参照。

## 3. 題材リポの準備（最初に一度だけ）

この週から週11まで、ずっと同じ [題材リポ（図書貸出管理API）](../project-repo/) を使います。まず動く状態にしておきましょう。

1. **題材リポのREADMEを読む**: [project-repo/README.md](../project-repo/README.md) の「1. このアプリは何をするか」「2. 全体像」に目を通す。
2. **動かしてみる**: 同READMEの「3. 動かし方」に沿って、`schema.sql` を流し、`./gradlew bootRun` で起動し、`curl` で `GET /api/books` が返ることを確認する。
   - **一度自分で動かす**と、「このAPIは実在して、こう動く」という手触りができ、コードが読みやすくなります。

> ⚠️ この週は**コードを変更しません**。読むだけです。直すのは週7から。安心して隅々まで開いてください（壊しても `git restore` で戻せます）。

## 4. この週の進め方（1課題のサイクル）

1. `exercises/NN-xxx.md` を開いて、**追う対象**（どの機能の流れを追うか）を確認する。
2. まず**自分でリポを開いて**、当たりをつける（どのフォルダ・どのファイルか）。
3. AIに要約させてよい（「このメソッドはどこから呼ばれる？」等）。ただし**AIの答えを、自分でそのファイルを開いて裏取り**する。
4. 追えた流れを **読解ノート**（各課題に雛形あり）に、**ファイル名・行番号を挙げて**書く。
5. 自分の言葉で「この機能は、どこを通って動くか」を説明できたら完成。

> この週の提出物は**読解ノート**です。「AIがこう言った」ではなく、「`BookController.java:41` で受けて、`BookService.java:33` に渡して…」と、**自分で確かめた事実（ファイル:行）**が書けていることがゴールです。

## 7. もっとやりたい人へ（追加課題）

- `POST /api/lendings/{id}/return`（返却）の流れも、在庫が**戻る**ところまで自分で追ってみる。
- `GET /api/books?category=技術書` の絞り込みが、どこで（どのファイルの何で）効いているかを追う（ヒント: `<if>`）。
- AIに「このリポの`available_count`はどこで増減する？」と聞き、返ってきた箇所を**全部**自分で開いて、本当にそこだけか確かめる（週7の影響範囲の予行演習）。

# 週6: 既存コードを読み解く — AIを相棒に、初見の中規模リポを歩く

ここから、研修の題材が変わります。これまでは「自分でゼロから作る」課題でした。今週からは**他人が書いた、すでに動いているシステム**——[題材リポ（図書貸出管理API）](../project-repo/)——に向き合います。
現場であなたが最初に任される動きは「ゼロから作る」ではなく、**既存のコードを読んで、直して、足す**こと。その第一歩が「読む」です。
全体の進め方・AI利用ルール・質問テンプレート・日報フォーマットは、先に [研修トップのREADME](../README.md) を読んでください。

> この週は第2フェーズ（AI協働）の後半の入口です。**AIにコードを読ませて要約させてよい**——ただし週5で身につけた「疑って裏を取る」構えをそのまま使います。**AIの要約を鵜呑みにせず、必ず自分でコードを開いて確かめる**。これが週7以降（安全な改修・参画）で「壊さず直す」ための土台になります。

---

## 1. この週の狙い（到達目標）

> **初見の中規模リポを渡されたら、AIの助けも借りて、全体像と該当箇所を自力で把握できる。**

現場に配属されると、あなたは**自分が書いたのではない、大きめのコードベース**にいきなり参加します。仕様書が完璧に揃っていることは稀で、「この機能どこで動いてるの？」を**コードから自分で探す**力が要ります。

この週で身につけること:

- **中規模リポの歩き方**: どこから読み始めるか（エントリポイント）、フォルダ構成から役割を推測する
- **処理フローを追う**: 1つのAPIが、Controller → Service → Mapper → XML(SQL) と、どのファイルのどの行を通って動くかを追う
- **3層構造の地図化**: 「窓口・判断・DB出し入れ」のどこに何があるかを、自分の言葉で地図にする
- **AIの要約を裏取りする読み方**: AIに「このコードは何をしている？」と要約させ、**その要約が本当か自分でコードを開いて確かめる**

> 用語メモ: **エントリポイント** … プログラムの入口。Spring Bootアプリなら `main` メソッドのある起動クラス（この題材では `LibraryApplication.java`）や、外からのリクエストを最初に受ける Controller。
> 用語メモ: **処理フロー** … 1つの操作（例: 本を借りる）が、どのファイルのどのメソッドを、どの順で通って実現されるかの流れ。

## 2. AI利用区分（この週のルール）

✅ **週6は、AIを「読解の相棒」として使ってよいです。** ただし条件があります。

- ✅ AIに「このファイルは何をしている？」「この処理はどこから呼ばれる？」と聞いてよい
- ✅ ただし **AIの要約・回答を鵜呑みにしない**。必ず**自分でそのファイルを開き、その行を見て**確かめる
- 🚫 「AIがこう言ったから」だけで完了にするのは不可。**最終的な理解は自分の言葉で**説明できること

> 週5で「AIは自信満々に間違える」を体で知りましたね。読解でも同じです。AIは「たぶんここでしょう」を断言します。**それが本当にそのファイル・その行か**を、自分の目で確認する。この裏取りが、週7で「壊さず直す」ときに効いてきます。

理由の詳細は [研修トップのREADME「2. AI利用ルール」](../README.md#2-ai利用ルール最重要必ず守る) を参照。

> この週の提出物は**読解ノート**です。「AIがこう言った」ではなく、「`BookController.java:41` で受けて、`BookService.java:33` に渡して…」と、**自分で確かめた事実（ファイル:行）**が書けていることがゴールです。

### コラム: 識別子の英語を読む（読解の、地味だけど本当の急所）

初見のコードが読めない原因は、たいてい文法ではありません。**名前（識別子）が英語だから**です。`incrementAvailable` を見て手が止まるのは、Javaが分かっていないからではなく、単語が分からないだけ。ここでつまずくのは当たり前で、恥ずかしいことではありません。

> 用語メモ: **識別子** … クラス名・メソッド名・変数名など、プログラマが自分で付けた名前のこと。日本語は使わない慣習なので、ほぼ全部が英語（の組み合わせ）になります。

コツは2つだけです。

1. **大文字で切る**。`incrementAvailable` → `increment` + `Available`。`markReturned` → `mark` + `Returned`。この書き方を**キャメルケース**（ラクダの背中のコブ）と呼びます。切ってから1語ずつ調べれば、たいてい意味が通ります。
2. **分からない単語は、その場で調べる**。AIに「`decrementAvailable` は英語として何をする名前？」と聞くのが速いです。**これはAIに答えを書かせているのではなく辞書を引いているだけ**なので、どの週でも遠慮なくやってください。

題材リポ（と週7〜8）で繰り返し出てくる単語を、先に置いておきます。**丸暗記はしなくていいので、迷ったらここに戻ってきてください。**

| 単語 | 意味 | どこで出てくるか |
|---|---|---|
| `lending` / `lend` | 貸出 / 貸す | 貸出まわり全体（`LendingService`） |
| `return` | 返却する / 返す | 返却処理（`returnBook`）※「値を返す」の return と同じ単語 |
| `available` | 利用できる（＝いま貸せる） | `available_count` … 貸出可能な在庫数 |
| `increment` / `decrement` | 1つ増やす / 1つ減らす | `incrementAvailable`＝在庫を1戻す、`decrementAvailable`＝在庫を1減らす |
| `due` / `overdue` | 期限 / 期限を過ぎた（延滞） | `dueDate`＝返却期限、`isOverdue`＝延滞しているか |
| `mark` | 印を付ける（状態を変える） | `markReturned`＝「返却済み」の印を付ける |
| `count` | 個数 | `available_count`＝貸せる冊数 |
| `assert` | 断言する | テストの `assertThat` / `assertEquals`（＝アサーション。週4・週8） |

`incrementAvailable` は「increment（1増やす）＋ Available（貸せる数）」＝**貸せる数を1増やす**。名前が読めた瞬間、そのメソッドが何をするかは**読む前に半分わかります**。これが効いてくるのが、週7（安全な改修）以降です。

### コラム: 1行に詰まった処理を、ほどいて読む

手が止まるもう一つの原因が、**1行に処理が何段も詰まっている**ことです。題材リポの `LendingController` に、こんな行があります。

```java
return new LendingResponse(lendingService.returnBook(id, LocalDate.now()));
```

左から読むと「まず `LendingResponse` を作って…」と読みたくなります。でも**動く順番は、内側から外側へ**です。ここを読み違えるのは非常によくあることで、書いた本人が数日後に読み違えることもあります。

> 用語メモ: **入れ子（ネスト）** … メソッドを呼んだ結果を、そのまま別のメソッドの引数として渡す書き方。`a(b(c()))` のように括弧が重なります。

コツは1つだけです。**いちばん内側の括弧から順に、変数に入れてほどく。**

```java
LocalDate today = LocalDate.now();                       // ① 今日の日付を作って
Lending lending = lendingService.returnBook(id, today);  // ② それで返却処理をして、貸出を受け取って
LendingResponse response = new LendingResponse(lending); // ③ それを包んで
return response;                                         // ④ 外へ返す
```

ほどくと、**動く順番が「上から下」になります**。さっきの1行は、この4行を畳んだものでした。

そして、ほどくと見えてくるものがあります。**変数が、メソッドとメソッドの「つなぎ目」になっている**ことです。

- `lendingService.returnBook(...)` の**出口**が `lending`
- その `lending` が、`new LendingResponse(...)` の**入口**

メソッドは「何かを受け取って、何かを返す箱」で、変数はその箱と箱をつなぐ線です。**畳んだ1行では、この線が消えます。** 読みにくいのは、あなたの理解が足りないからではなく、線が省略されているからです。

> **では、なぜ現場のコードは畳んであるのか**: 短いからです。慣れた人には、畳んであるほうが速く読めます。だから既存コードはたいてい畳んであります。**あなたがやることは、書き方を変えることではなく、頭の中でほどけるようになること**です。ほどければ、畳んだままでも読めます。

**やってみる**: `training/project-repo/.../lending/LendingController.java` を開いて、`returnBook` の1行を上の①〜④のように分けて、紙かメモに書き出してみてください。**ファイルを書き換える必要はありません。** ほどけたら、次の3つに答えられるはずです。

- [ ] いちばん最初に動くのはどれか
- [ ] `returnBook` が返してきたものは、次にどこへ渡っているか
- [ ] このメソッドが最後に外へ返しているものは何か

> 迷ったら、`Ctrl` を押しながらメソッド名をクリックすると定義に飛べます。**そこに書いてある戻り値の型が、その箱の「出口」**です。この「飛んで確かめる」が、この週ずっと使う読み方になります。

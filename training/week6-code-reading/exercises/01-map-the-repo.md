# 課題01: 全体像を地図化する

**所要時間の目安**: 90分
**AI利用区分**: ✅ 読解の相棒としてAIを使ってよい。ただし要約は自分でコードを開いて裏取りすること。

---

## 1. 背景・狙い（現場でどう使うか）

初見のリポに入ったとき、いきなり1行目から読み始めるのは効率が悪いです。まず**全体像（どこに何があるか）の地図**を作ります。地図があると、「この機能を直したい」となったとき、当たりをつけて最短で該当箇所にたどり着けます。

この課題では、[題材リポ（図書貸出管理API）](../../project-repo/) を、**3層構造とパッケージ構成の観点で地図化**します。細部は追いません。「森を見る」練習です。

---

## 2. やること

### ステップ1: リポを「上から」眺める

題材リポのトップを開き、フォルダ構成を眺めます。

```bash
# 題材リポのソースの木を見る（build/や.gradle/は無視してよい）
cd ../../project-repo
find src/main -type f | sort
```

- `com.example.training` の下に、どんなパッケージ（フォルダ）があるか。
- 各パッケージには、どんな種類のファイル（Controller / Service / Mapper / エンティティ / DTO）があるか。

### ステップ2: AIに全体像を要約させる（そして裏取りする）

AIに、例えばこう聞いてみます。

```
このSpringBootリポジトリのパッケージ構成を教えて。
各パッケージが3層構造（Controller/Service/Mapper）のどの役割かも。
```

返ってきた要約を、**そのまま信じない**。`book` / `member` / `lending` / `common` の各フォルダを実際に開いて、AIの言うファイルが本当にそこにあるか、役割が合っているかを確かめます。

### ステップ3: 自分で地図を書く

確かめた事実をもとに、**自分の言葉で**地図を書きます（下の読解ノート）。README（[project-repo/README.md](../../project-repo/README.md) の「2. 全体像」）とも見比べて、自分の理解が合っているか確認します。

## 4. つまずきポイントとヒント

<details>
<summary>どのファイルが「どの層」か見分けられない</summary>

名前とアノテーションがヒントです。`@RestController` が付いていれば窓口（Controller）、`@Service` なら判断・処理（Service）、`@Mapper` ならDB出し入れ（Mapper）。週3の「3層のどこに何を書くか」を思い出してください。
</details>

<details>
<summary>エントリポイントが分からない</summary>

`main` メソッドを探します。`grep -rn "public static void main" src/main` で一発です。`@SpringBootApplication` が付いているクラスが起動クラスです。
</details>

<details>
<summary>common/ って何のフォルダ？</summary>

特定のエンティティ（book/member/lending）に属さない、**共通の部品**を置く場所です。ここでは例外処理（エラーをHTTPの404や409に変換する仕組み）が入っています。中を開いて確かめてみてください。
</details>

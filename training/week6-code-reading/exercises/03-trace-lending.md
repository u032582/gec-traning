# 課題03: 貸出で在庫が減るまでを追う（POST /api/lendings）

**所要時間の目安**: 120分
**AI利用区分**: ✅ 読解の相棒としてAIを使ってよい。ただし複数ファイルを横断するので、AIの要約は特に念入りに裏取りすること。

---

## 1. 背景・狙い（現場でどう使うか）

課題02は1本道の単純なフローでした。実際の現場のコードは、**複数のファイル・パッケージを横断し、途中に業務ルール（判断）が挟まる**ものがほとんどです。この課題では、このアプリの**核**である「本を借りると在庫が1減る」処理を追います。

`POST /api/lendings` は、`lending` パッケージから始まり、`member`（借り主の確認）と `book`（在庫を減らす）を横断し、DB側のSQLにも仕掛けがあります。この**横断する流れ**を、ファイル名・行で追い切るのが目標です。ここを追えれば、週7で「在庫まわりを直すと、どこに響くか」が読めるようになります。

## 2. やること

### ステップ1: 入口から、在庫が減る場所まで追う

`POST /api/lendings` を受ける Controller から始めて、**「在庫（available_count）が実際に1減る場所」までの流れ**を追います。途中で通る「判断」も拾ってください:

- 借り主（member）が実在するかの確認は、どこでやっているか
- 在庫を減らす処理は、どのファイルのどのメソッドか
- 在庫が0のとき「貸せない」と弾くのは、どこか

追う流れ（自分で埋める。課題02より段数が多い）:
```
LendingController の受け口
  → LendingService の lend メソッド
    → （借り主の実在確認は？どこを呼ぶ？）
    → （在庫を減らすのは？どのMapperのどのメソッド？）
      → XML の実際のUPDATE文（在庫を減らすSQL）
    → （貸出記録を作るのは？）
```

### ステップ2: 「在庫が0なら貸せない」は、どこで守られているか

このアプリは、在庫0の本を借りようとすると**409（貸出できません）**を返します。ここが面白いところ:

- Service（Java側）にも「在庫0なら弾く」判断があります。どの行か。
- **SQL（XML側）にも仕掛けがあります**。在庫を減らすUPDATE文の `WHERE` に、何が書いてあるか。なぜそれが「最後の1冊を二重に貸す事故」を防ぐのか。

> ここは**AIが要約を間違えやすい所**です。「Serviceで在庫チェックしています」で終わりがちですが、実際はSQLの `WHERE` にも守りがあります。**両方を自分で開いて確かめて**ください。

### ステップ3: 2つのテーブル更新が「1まとまり」な理由

貸出は「`lendings` に1件足す」と「`books` の在庫を1減らす」の**2つの更新**をします。この2つが「両方成功か、両方失敗」でないと在庫が狂います。それを保証している**目印（アノテーション）**が `LendingService` にあります。何というアノテーションか、探してください。

### ステップ4: AIに要約させ、念入りに裏取り

AIに「POST /api/lendings で在庫が減るまでの流れをファイル名・行で」と要約させてよいですが、**ステップ2のSQL側の守り**と**ステップ3のアノテーション**を、AIが正しく拾えているか特に注意して、自分で確かめてください。

## 4. つまずきポイントとヒント

<details>
<summary>Serviceが book と member の両方を呼んでいて、流れを見失う</summary>

`LendingService` の `lend` メソッドを上から順に読んでください。「①借り主の確認 → ②在庫を減らす → ③記録を作る」の順にコメントも付いています。1行ずつ、呼んでいる相手（`memberService` なのか `bookMapper` なのか `lendingMapper` なのか）を指差し確認すると迷いません。
</details>

<details>
<summary>「SQL側の守り」が何のことか分からない</summary>

在庫を減らすUPDATE文（`BookMapper.xml` の `decrementAvailable`）の `WHERE` 句をよく見てください。`id = ...` の他に、もう1つ条件が付いています。その条件があるおかげで「在庫が残っているときだけ減る」＝在庫がマイナスにならない・最後の1冊を2人に貸さない、が保証されます。コメントにも説明があります。
</details>

<details>
<summary>アノテーションって何を探せばいい？</summary>

「2つの更新をまとめて成功/失敗させる」仕組みは、Spring では `@Transactional` という目印で表します。`LendingService.java` の中を `@Transactional` で探してみてください。なぜ貸出・返却の両方に付いているか、コメントを読むと分かります。
</details>

# 課題01: 効くプロンプトで書かせて、検証する

**所要時間の目安**: 90分
**AI利用区分**: ✅ AIにコードを書かせてよい。むしろ「書かせて検証すること」がこの課題です。

---

## 1. 背景・狙い（現場でどう使うか）

現場でAIにコードを頼むとき、雑に「◯◯するやつ作って」と言うと、**それっぽいが仕様とズレたもの**が返ってきます。プロンプト（AIへの指示）に、**仕様・制約・期待出力**をきちんと渡せるかで、返ってくるものの質が変わります。

そして——**返ってきたコードは、動いても信じない**。仕様どおりか、境界値を落としていないかを、自分で確かめます。この課題では「効くプロンプトで書かせる → レビュー観点で検証する」の一往復を練習します。

> 用語メモ: **プロンプト** … AIへの指示文。「何を・どんな制約で・どんな入出力で」を具体的に書くほど、返ってくるコードの精度が上がります。

---

## 2. お題（既習の週1・課題03をAIにやらせる）

題材は、あなたが**週1・課題03で自分の手で書いた `Ex03`** です（[week1の03-if.md](../../week1-java-basics/exercises/03-if.md)）。
なかでも **`isLeapYear`（うるう年判定）** を使います。この仕様は「400→100→4の順で考える」という**間違えやすい落とし穴**があり、AIの検証練習にぴったりです。

> なぜ既習の課題か: **あなたは正解を知っている**からです。自分の手書き解（`solutions/Ex03.java`／自分の提出物）が手元にあるので、AIの出力が正しいかを突き合わせて判定できます。正解を知っている題材でAIの癖を掴むのが、この週の狙いです。

## 3. 手順

### ステップ1: わざと"雑な"プロンプトで書かせる（比較用）

まず、AIにこう頼んでみてください（Agentモードでも、チャットでコードをもらう形でもよい）。

```
Javaで、うるう年かどうかを判定するメソッドを書いて。
```

返ってきたコードを、いったんそのまま手元にメモしておきます（あとで比べます）。

### ステップ2: "効く"プロンプトで書かせる

次に、**仕様・制約・期待出力を渡して**書かせます。例:

```
Javaで、うるう年を判定する boolean isLeapYear(int year) を書いて。
判定ルールは次の順で:
  1. 400で割り切れる年は true
  2. （1でなく）100で割り切れる年は false
  3. （上記以外で）4で割り切れる年は true
  4. どれにも当てはまらなければ false
期待する結果: isLeapYear(2000)=true, isLeapYear(1900)=false,
             isLeapYear(2024)=true, isLeapYear(2023)=false
外部ライブラリは使わず、算術演算だけで書いて。
```

### ステップ3: 検証する（ここが本番）

ステップ2で返ってきたコードを、**§4のレビュー観点で1つずつ確かめます**。特に:

- **動くか**: `Ex03` に貼って、あなたが週1で使った `Ex03Test.java` を流す（`javac Ex03.java Ex03Test.java && java Ex03Test`）。うるう年の4ケースが PASS するか。
- **正しいか**: `isLeapYear(1900)` は `false` になっているか？（ここが一番落としやすい。`year % 4 == 0` だけで書くAIは1900をtrueにしてしまう）
- **説明できるか**: なぜ400→100→4の順なのか、自分の言葉で言えるか。

### ステップ4: 2つのプロンプトの結果を比べる

ステップ1（雑）とステップ2（効く）で、返ってきたコードはどう違いましたか？
- 引数の型・メソッド名は仕様どおりだったか
- 1900年の判定は合っていたか
- どちらが自分の手書き解（週1）に近かったか

## 5. つまずきポイントとヒント

<details>
<summary>AIが `year % 4 == 0` だけの簡単な判定を返してきた</summary>

それは**よくある間違い**です。`1900 % 4` は `0` なので、その式だと1900年が「うるう年（true）」になってしまいます。正しくは 400→100→4 の順。**AIが自信満々でも、1900年を自分で試すと見抜けます**。これがまさに「検証」です。
</details>

<details>
<summary>「動いたからOK」で終わっていいか不安</summary>

ダメです。この週の主役は「動くコード」ではなく「検証ノート」。**なぜ動くのか・どこを疑って裏を取ったか**を書けて、初めて完成です。動くだけなら週3〜4と同じになってしまいます。
</details>

<details>
<summary>自分の週1の手書き解が見つからない</summary>

</details>

# 課題02: ハルシネーションを踏んで、見抜く

**所要時間の目安**: 90分
**AI利用区分**: ✅ AIにコードを書かせてよい。この課題は「AIの間違いを自分で見つける」練習です。

---

## 1. 背景・狙い（現場でどう使うか）

AIは、**実在しないメソッド・古いAPI・それっぽいが間違った書き方**を、自信満々で出力することがあります。これを **ハルシネーション** と呼びます。現場でこれに気づかず貼ると、「コンパイルが通らない」「動くが仕様と違う」「非推奨で将来消える」といった地雷を踏みます。

この課題の狙いは、**一度自分の手で"踏んで"、見抜き方を体で覚える**ことです。知識として「気をつけよう」ではなく、実際にコンパイルエラーやおかしな挙動に出会い、**自分で裏を取って弾く**経験をします。

> 用語メモ: **ハルシネーション** … AIが、それっぽいが事実でないこと（存在しないメソッド名・古いAPIなど）を自信満々に出力すること。「AIが言っているから正しい」は通用しません。**実在するかは、自分で確かめる**しかありません。

---

## 2. お題（既習の週1・コレクション/Streamをネタにする）

題材は、週1で学んだ **List / Map / Stream**（[week1の06-list.md](../../week1-java-basics/exercises/06-list.md) 〜 [12-stream.md](../../week1-java-basics/exercises/12-stream.md)）です。この辺りは、AIが**存在しないメソッド名**をでっち上げやすい領域なので、ハルシネーションに出会いやすいです。

---

## 3. 手順

### ステップ1: あえて"引っかかりやすい"頼み方をする

AIに、次のような**少しあいまいで凝った**お題を投げてみてください（1つ選ぶ）。

- 「`List<Integer>` から、重複を消して、大きい順に並べて、最初の3件だけ取り出すコードを、Stream1行で書いて」
- 「`List<String>` を、要素の文字数をキーにした `Map<Integer, List<String>>` に一発で変換して」
- 「`Map<String,Integer>` を、値の大きい順に並べ替えて表示するコードを書いて」

AIによっては、`.distinctBy(...)` や `.sortDescending()` や `.takeFirst(3)` のような、**Javaに実在しないメソッド**を返してくることがあります（実在するのは `distinct()` / `sorted(Comparator.reverseOrder())` / `limit(3)` など）。

### ステップ2: 裏を取る（実在するか確かめる）

返ってきたコードのメソッドを、**そのまま信じずに確かめます**。裏の取り方は3つ:

1. **コンパイルしてみる**: 実際に `javac` に通す。存在しないメソッドなら `cannot find symbol` が出ます。**これが一番確実**。
2. **公式ドキュメントで探す**: `List` / `Stream` / `Map` に本当にそのメソッドがあるか。無ければハルシネーション。
3. **AIに聞き返す**: 「そのメソッドは標準ライブラリに実在しますか？ 出典は？」と問い直す。ただしAIの返事も鵜呑みにせず、最後は1か2で確定させる。

> ⚠️ 3だけで終えないこと。AIに「実在します」と言われても、**コンパイルが通らなければ実在しません**。最終判定はコンパイラです。

### ステップ3: 自分で正しい形に直す

ハルシネーションを見つけたら、**実在するメソッドに置き換えて、コンパイル・実行が通る形**にします。直したら、週1の自分の手書き解や、`Ex12`（Stream課題）の考え方と突き合わせて、結果が正しいか確認します。

> もし1回で実在しないメソッドが出なかったら: 別のお題に変える／もっと凝った要求にする、で高確率で"踏め"ます。踏めたらラッキー、くらいの気持ちで。

## 検証ノート（この課題の提出物・必ず埋める）

```
【AIに投げたお題（プロンプト）】
List<Integer> から、重複を消して、大きい順に並べて、最初の3件だけ取り出すコードを、Stream1行で書いて

【返ってきたコードの、疑わしかった箇所（メソッド名など）】
sortDescending() が怪しかった

【どうやって裏を取ったか（コンパイル/公式/聞き返し のどれで、結果どうだったか）】
javac で cannot find symbol: method sortDescending() が出た

【実在しなかった場合、正しい形にどう直したか】
sorted(Comparator.reverseOrder()) に置き換えて、[5, 3, 1] を確認


【この体験から学んだ「AIの間違いの見抜き方」を一言で】
見覚えのないメソッドはコンパイルで確かめる
```

## 4. 完成条件（自分で判定できる）

- [ ] AIの出力の中の**怪しい箇所を自分で特定**した
- [ ] コンパイル or 公式ドキュメントで**裏を取った**（AIの言葉だけで終えていない）
- [ ] （ハルシネーションがあった場合）実在するメソッドに直し、コンパイル・実行が通った
- [ ] 検証ノートを自分の言葉で埋めた

## 5. つまずきポイントとヒント

<details>
<summary>何度やっても実在するメソッドしか返ってこない</summary>

最近のAIは賢いので、素直なお題だと正解を返しがちです。**より凝った・あいまいな要求**（「一発で」「1行で」「いい感じに」）にすると、実在しないメソッドをでっち上げやすくなります。それでも出なければ、それはそれで「今回はハルシネーションが無かった」という**立派な検証結果**——ノートにそう書けばOKです（大事なのは"疑って裏を取った"事実）。
</details>

<details>
<summary>`cannot find symbol` の意味が分からない</summary>

「そのメソッド（またはクラス・変数）が見つからない」というコンパイルエラーです。ハルシネーションで**存在しないメソッドが呼ばれている**とき、まさにこれが出ます。エラーが出た＝見抜けた、ということ。喜んでいいサインです。
</details>

<details>
<summary>正しいメソッドが分からない</summary>

週1の [12-stream.md](../../week1-java-basics/exercises/12-stream.md) と `solutions/Ex12.java` に、`distinct()` / `sorted()` / `limit()` / `collect()` などの正しい使い方があります。まずそこを見て、AIの出力と突き合わせてください。
</details>

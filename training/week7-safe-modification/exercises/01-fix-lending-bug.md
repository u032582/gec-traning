# 課題01: バグ①を直す — 在庫切れなのに貸出記録ができてしまう

**所要時間の目安**: 90分
**AI利用区分**: ✅ AIに改修案を出させてよい。ただし「なぜ直るか」「影響範囲」を自分で言えること。

---

## 1. 背景・狙い（現場でどう使うか）

現場のバグ修正は「テストが赤い → コードを直す → 緑になる」の繰り返しです。この課題で、その1サイクルを体験します。あわせて、現場で一番大事な**「直す前に影響範囲を言う」**を練習します。

---

## 2. バグの症状（バグ票のつもりで読む）

> **バグ票**: 在庫が0冊の本を貸し出そうとしたとき、「貸出できません」とエラーになるべきなのに、
> **貸出記録が作られてしまう**。結果、実際には無い本を「貸した」ことになり、在庫の数字が壊れる。

対応するテストが `bug-scenarios/` にあります。まず赤を見ましょう。
```bash
cd ../bug-scenarios   # week7-safe-modification/bug-scenarios へ
./gradlew test
```
`貸出_在庫切れなら貸出記録は作られない()` が **FAILED** になっているはずです。このテストを開いて、**何を期待して落ちているか**を読んでください。

---

## 3. やること

### ステップ1: 原因を特定する
`bug-scenarios/src/main/java/com/example/training/lending/LendingService.java` の `lend` メソッドを読みます。`// TODO(bug-1)` の目印があります。「在庫を減らせなかった（`decremented == 0`）とき、どうすべきか」を考えてください。

### ステップ2: 影響範囲を**先に**言う（直す前に）
直す前に、改修ノートの「影響範囲」を埋めます。「ここに `if` を足すと、他のどのテスト・どの動きに影響するか？」を考える。**在庫がある正常な貸出（もともと緑のテスト）を、巻き込んで壊さないか？** を先に予想します。

### ステップ3: 小さく直す
AIに「このTODOをどう直すべきか」を聞いてもよいです。ただし**採用する前に、なぜそれで直るかを自分の言葉で**。直すのは `lend` メソッドの中だけ。テストは触りません。

> ヒント: 題材リポの正しい実装では、在庫が減らせなかったときに「本が存在しないなら404／存在するなら在庫切れで409」を投げ分けています。落ちているテストが要求している範囲で直せば十分です。

### ステップ4: 全テストを流す（リグレッション確認）
```bash
./gradlew test
```
- `貸出_在庫切れなら貸出記録は作られない()` が **緑** になったか
- **もともと緑だったテスト（正常な貸出など）が、赤に変わっていないか**（＝壊していないか）

両方OKで完成です。

---

## 改修ノート（この課題の提出物・必ず埋める）

```
【バグの原因（自分の言葉で）】


【どう直したか（変更点を1〜2行で）】


【なぜその変更で直るのか】


【影響範囲：この変更で他のどこに影響しうるか。壊していないことをどう確認したか】


【AIに案を出させた場合、その案をなぜ採用/修正したか】

```

## 4. 完成条件（自分で判定できる）

- [ ] `貸出_在庫切れなら貸出記録は作られない()` が緑になった
- [ ] もともと緑だったテストを1つも壊していない（`./gradlew test` の緑の本数が減っていない）
- [ ] 改修ノートに「なぜ直るか」「影響範囲」を書いた
- [ ] テストは書き換えていない（直したのは LendingService だけ）

## 5. つまずきポイントとヒント

<details>
<summary>直したら別のテストが赤くなった</summary>

それが**リグレッション**です。まさに今週防ぎたい事故。直し方が「在庫があるときの正常な貸出」まで巻き込んでいます。`decremented == 0`（在庫切れ）のときだけ弾き、`1`（減らせた）ときは今まで通り進む——**条件を正しく絞れているか**を見直してください。
</details>

<details>
<summary>404と409、どちらを投げればいい？</summary>

落ちているテスト `貸出_在庫切れなら貸出記録は作られない()` は、`BusinessRuleException`（→409）を期待しています。テストの `assertThatThrownBy(...).isInstanceOf(...)` の行を読めば、何を投げるべきか分かります。「テストが答えを教えてくれる」感覚をつかんでください。
</details>

<details>
<summary>AIに丸投げして緑になったが、なぜ直ったか説明できない</summary>

それは**まだ完成ではありません**（今週のルール）。緑になっても、「在庫0のとき、どの行が効いて記録作成を止めたのか」を自分の言葉で言えるまでがゴールです。言えないなら、その行をコメントアウトして再度テストを流し、赤に戻ることを確かめると腹落ちします。
</details>

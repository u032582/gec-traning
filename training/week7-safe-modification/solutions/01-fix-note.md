# 模範: 課題01 改修ノート（記入例）

> これは**記入の見本**です。直し方は一通りではありません。大事なのは「なぜ直るか」と「影響範囲」を自分で言えていること。

---

【バグの原因（自分の言葉で）】
 `lend` メソッドで、在庫を減らす `decrementAvailable` の戻り値（減らせた件数）を見ずに、そのまま貸出記録の insert まで進んでいた。在庫0の本は `decrementAvailable` が0を返す（1行も減らせない）が、その0を無視していたので、在庫が無いのに記録だけできてしまっていた。

【どう直したか（変更点を1〜2行で）】
 `decremented == 0` のとき、本が存在しなければ NotFoundException（404）、存在すれば BusinessRuleException（409＝在庫切れ）を投げ、insert まで進まないようにした。

【なぜその変更で直るのか】
 在庫を減らせなかった時点で例外を投げて処理を打ち切るので、その後の `lendingMapper.insert(...)` に到達しない。だから「在庫0なのに貸出記録ができる」が起きなくなる。落ちていたテストは「在庫切れで例外」かつ「insert が呼ばれない」の両方を要求していたので、両方満たせた。

【影響範囲：この変更で他のどこに影響しうるか。壊していないことをどう確認したか】
 変更したのは `lend` の中だけ。影響しうるのは「貸出」まわりのテスト。
 - 正常な貸出（`decremented == 1`）のときは新しい `if` の条件に入らないので、今まで通り insert される → `貸出成功...` テストは緑のまま。
 - 返却系（returnBook）には触っていないので影響なし。
 `./gradlew test` で、緑だったテストが赤に変わっていないことを確認した（リグレッションなし）。

【AIに案を出させた場合、その案をなぜ採用/修正したか】
 AIは「`if (decremented == 0) throw new BusinessRuleException(...)`」だけを提案してきた。それでも落ちているテストは緑になるが、題材リポの正しい実装に合わせ「本が存在しないなら404」の分岐も足した（テストの `bookMapper.findById` のスタブがそれを示唆していた）。AIの最小案を、既存の仕様に馴染む形に自分で広げた。
